# 问题库与数据资源

## 问题体系

发布版注册 155 个问题，覆盖解析基准、约束、多模态、稀疏大规模和实际应用。完整名称
应通过代码查询，以安装版本为准：

```python
from ascendmoea import list_problems

for name in list_problems():
    print(name)
```

## 主要基准族

| 类型 | 问题族 | 数量或范围 | 关注性质 |
|---|---|---:|---|
| 通用 | ZDT | ZDT1 至 ZDT6 | 双目标形状、非凸与不连续前沿 |
| 通用 | DTLZ | DTLZ1 至 DTLZ7 | 可变目标数与退化前沿 |
| 大规模 | LSMOP | LSMOP1 至 LSMOP9 | 变量分组和大维决策空间 |
| 稀疏 | SMOP | SMOP1 至 SMOP8 | 稀疏最优决策结构 |
| 约束 | CF | CF1 至 CF10 | 非线性约束和断裂可行前沿 |
| 约束 | DASCMOP | DASCMOP1 至 DASCMOP9 | 可调困难度约束 |
| 约束 | LIRCMOP | LIRCMOP1 至 LIRCMOP14 | 大不可行区域与复杂约束 |
| 多模态 | MMF | 多个 MMF 变体 | 多 Pareto 集与映射结构 |
| 多模态 | MMMOP | MMMOP1A 至 MMMOP6D | 多层决策空间景观 |
| 多模态 | IDMP | 基础与扩展变体 | 决策空间等价解 |
| 多模态 | SYM-PART、Omni、poly | 多个变体 | 对称、周期和多项式结构 |

## 实际与组合问题

实际问题包括 RWMOP1 至 RWMOP10，以及 MONRP、MOTSP、MPDMP、RLP、UECLP、
application、mQAP、map 等任务。稀疏实际问题包括 `Sparse_KP`、`Sparse_PM`、
`Sparse_PO` 和 `Sparse_SR`。

这类问题可能具有以下特点：

- 构造函数从包资源读取 MAT 数据；
- 决策变量可能是整数、标签、二进制或排列编码；
- 可用的维数和目标数受数据实例限制；
- 单次评价可能包含距离矩阵、图结构或组合约束。

使用前应读取具体类的 docstring 和构造参数，不要把解析函数的 `d` 参数规则直接套用到
实际问题。

## 直接导入与名称工厂

合法 Python 标识符会在 `ascendmoea.problems` 中直接导出：

```python
from ascendmoea.problems import DTLZ2, LIRCMOP5, RWMOP3

p1 = DTLZ2(n=100, m=3, d=12, max_fe=10_000)
p2 = LIRCMOP5(n=100, max_fe=10_000)
p3 = RWMOP3(n=100, max_fe=10_000)
```

任何注册名都可通过工厂构造：

```python
from ascendmoea import create_problem

problem = create_problem("SYM-PART simple", n=100, max_fe=10_000)
```

对于含空格、连字符或其他非标识符的名称，必须使用工厂。

## 编码约定

`Problem.encoding` 中每个变量的编码值为：

| 值 | 编码 |
|---:|---|
| 1 | 实数 |
| 2 | 整数 |
| 3 | 标签 |
| 4 | 二进制 |
| 5 | 排列 |

基础初始化器会按编码批量生成决策，并对整数、标签和二进制执行与参考语义一致的舍入与
边界修复。用户算法调用变异算子时，应选择支持对应编码的入口。

## 参考数据与指标

`problem.optimum` 是延迟生成并缓存的目标空间参考点，`problem.pf` 是可选的绘图表示。

```python
reference_objectives = problem.optimum
drawable_front = problem.pf
```

两者用途不同：指标应使用足够密集且定义明确的参考目标集，绘图表示可能只是曲线、网格
或 `None`。多模态决策空间指标需要额外的参考 Pareto 集；若问题类未公开提供，应从
基准定义生成并随实验数据固化。

## 包资源访问

数据文件位于安装包的 `ascendmoea/vendor` 资源树，由问题类按包位置解析。发布 wheel
时必须检查所有 MAT 文件已包含：

```bash
python -m pip wheel . --no-deps -w dist
python -m zipfile -l dist/AscendMOEA-0.1.0-py3-none-any.whl
```

不要在问题实现中使用依赖当前目录的相对路径，也不要把服务器绝对路径写进发行代码。

## 问题级验证

每个问题至少进行以下检查：

1. 构造后边界长度等于 `D`，编码长度等于 `D`；
2. `initialization(k)` 返回 `k` 行，所有值有限；
3. 目标列数等于 `M`，约束列数在不同批次间稳定；
4. CPU 和 NPU 在相同输入上的目标与约束在容差内一致；
5. 参考前沿与固化的高精度参考结果在统计量和指标上保持一致；
6. 实际问题在安装后的 wheel 中仍能找到数据资源。
