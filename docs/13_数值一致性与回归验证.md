# 数值一致性与回归验证

## 验证目标

张量化和设备适配可以改变执行方式，但不能改变问题定义、约束方向、种群规模、终止条件、
排序规则或随机状态消费约定。验证应从固定输入开始，逐层覆盖问题、算子、算法轨迹、质量
指标和运行资源，不能只依据最终一次运行是否成功。

## 张量形状约定

核心对象采用以下二维布局：

- 决策矩阵：`[N, D]`；
- 目标矩阵：`[N, M]`；
- 约束矩阵：`[N, C]`；
- 参考向量：`[K, M]`；
- 个体两两关系：`[N, N]`。

实现中应通过 `reshape`、`unsqueeze` 和显式维度参数说明广播方向。测试必须覆盖 `N=1`、
单约束、多目标、不同决策维数和空约束矩阵，防止自动压缩掩盖形状错误。

## 索引、舍入与平局

排序和选择的回归测试至少检查：

- 索引值域和边界端点；
- 升序、降序和稳定排序；
- 相同适应度个体的原始顺序；
- 最后一层前沿的保留数量；
- NaN 和无穷值的拒绝路径；
- 实数、整数、标签、二进制和排列编码的修复结果；
- 半整数舍入和排列值域。

平局规则会改变后续随机数消费和完整轨迹，因此应保存索引结果，而不只比较排序后的数值。

## 固定输入测试

每个问题和公共算子都应建立一组不可变输入，覆盖边界值、随机值、重复值和数值消去区域。
CPU `float64` 结果作为高精度夹具，NPU `float32` 结果使用预先声明的绝对与相对容差：

```text
abs(actual - expected) <= atol + rtol * abs(expected)
```

容差按问题族和数值范围固定，不能在看到失败结果后临时放宽。离散索引、前沿号、布尔掩码
和种群行顺序应精确一致。

## 问题级验证

1. 构造后检查 `N`、`M`、`D`、边界和编码。
2. 对固定决策矩阵比较目标、约束和修复后决策。
3. 对不同批量大小重复计算，确认批量维不改变单行结果。
4. 验证参考前沿、参考点和实际数据资源可以从安装包读取。
5. 在 CPU 与 NPU 上检查有限值、dtype、device 和容差。
6. 对约束边界、极小残差和大维度输入增加专门回归样本。

## 算子级验证

选择、变异和环境筛选应分别保存输入、随机状态和输出。无随机算子要求逐值相等；随机算子
应在固定 seed 下比较输出、随机状态和随机张量调用数量。涉及顺序依赖的截断或局部搜索时，
还要比较每一步选择索引，确认加速没有把顺序更新错误地变成同步更新。

## 算法级验证

算法回归分为三层：

1. **最小烟雾**：小种群和小评价预算，验证所有算法能构造、迭代和终止。
2. **轨迹回归**：固定 seed，保存每代 `decs`、`objs`、`cons`、排序状态和实际 FE。
3. **统计回归**：在固定配置下运行多个 seed，比较 HV、IGD、IGD+、IGDX、可行率和运行时间
   的分布。

若实现调整明确保留随机调用顺序，轨迹张量应在同 dtype、同设备下逐值一致。若设备精度或
随机后端不同，则先通过固定输入门禁，再用预先定义的分布阈值判断算法级一致性。

## 无可行解和未定义指标

约束算法可能在给定预算内没有找到可行解。此时可行集上的 HV、IGD 和 IGD+ 没有定义，
结果应保存为 JSON `null`，并同时记录：

- `feasible_rate=0`；
- `nondominated_count=0`；
- `best_cv` 和 `mean_cv`；
- 明确的 `undefined_no_feasible_solution` 状态。

不能把未定义指标伪造成 0，也不能在聚合时静默删除这类 run。统计结果应单独报告无可行解
比例，并对有限指标和可行率分别分析。

## 性能合理性检查

异常快和异常慢都需要复核。检查项包括实际 FE、种群规模、设备同步、首次编译、主机设备
传输、CPU 线程、重复排序、隐藏循环和内存退化。性能记录必须同时保存 `compute_time_s`、
`total_time_s`、主机 RSS、系统内存、NPU 进程 HBM 和框架分配器统计。

## 回归记录模板

每次修改至少记录：

- 修改文件和源码 SHA-256；
- 受影响的算法、问题或算子；
- 固定输入及误差上界；
- 轨迹、FE 和随机状态结果；
- 多种子指标统计；
- CPU/NPU 时间和内存；
- 失败输入、修复方法和验证日期。

只有结构、数值、轨迹、统计和设备门禁全部达到预先定义的标准，才能把修改纳入稳定版本。
