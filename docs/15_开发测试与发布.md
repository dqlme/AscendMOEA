# 开发测试与发布

## 源码布局

```text
AscendMOEA/
  src/ascendmoea/
    algorithms/       # one public algorithm per module
    problems/         # problem families and registries
    operators/        # stable public operator namespace
    vendor/           # packaged reference data
    core.py            # Population, Problem, Algorithm
    device.py          # device, dtype, seed, synchronization
    workflow.py        # run orchestration and monitors
    metrics.py         # quality indicators
  examples/
  tests/
  tools/
  docs/
  pyproject.toml
```

新算法应放在独立 `.py` 文件中，并在 `algorithms/__init__.py` 注册和导出。新问题通常按
问题族组织，每个公开问题必须映射到独立类；不能用匿名函数作为注册组件，因为这会破坏
反射、文档和稳定构造。

## 代码标准

- Python 3.9 及以上，源码使用 ASCII，用户文档可使用中文；
- 所有公开和内部函数、类、模块都有英文 docstring；
- docstring 说明参数、返回值、形状、设备和可能的异常，而不是重复函数名；
- 不保留无关叙述、迁移痕迹或过期项目名称；
- 算法代际主循环以外尽量使用张量化实现；
- 新张量显式继承设备和 dtype；
- 不在公共 API 中暴露内部文件布局。

## 本地静态检查

```bash
python tools/normalize_docstrings.py . --check
python -m ruff check src tests examples tools
python -m compileall -q src tests examples tools
```

docstring 工具只用于发现缺口，自动生成的泛化描述必须人工改写为有意义的接口说明。

## 单元与集成测试

```bash
python -m pytest
```

测试覆盖：

- 注册、重名和工厂构造；
- 自定义问题批量评价；
- 公共算子的形状、值与设备；
- 工作流同步计时和监控生命周期；
- 顶层公开 API；
- 实际问题资源在安装包中的加载。

算法和问题的全量烟雾测试由 `tools/validate_release.py` 执行：

```bash
python tools/validate_release.py --device cpu --cpu-threads 1 \
  --output validation_cpu.json
python tools/validate_release.py --device npu:0 \
  --output validation_npu0.json
```

烟雾测试验证可运行性，不能替代 `N=100`、`max_fe=10_000` 以上的质量对照。

## 构建 wheel

```bash
python -m build
# or
python -m pip wheel . --no-deps -w dist
```

构建后在全新临时环境中安装 wheel，禁止从源码目录导入：

```bash
python -m venv /tmp/ascendmoea-wheel-test
source /tmp/ascendmoea-wheel-test/bin/activate
python -m pip install /path/to/dist/AscendMOEA-0.1.0-py3-none-any.whl
cd /tmp
python -c "import ascendmoea; print(ascendmoea.__version__)"
```

昇腾环境使用现有匹配的设备依赖并 `--no-deps` 安装 wheel。

## 发布门禁

发布前必须满足：

1. 旧名称全文检索为零；
2. Python 语法、docstring、ruff 和 pytest 全部通过；
3. wheel 包含全部 MAT 资源且可离开源码目录运行；
4. 20 个内置算法、155 个内置问题和全部公开算子在 CPU 通过；
5. 自定义算法和自定义问题示例在 CPU 与 NPU 通过；
6. 所有兼容算法在 NPU 完成烟雾测试；
7. 固定输入 CPU/NPU 数值对照通过；
8. 固化参考输出和上一个稳定版本的指标对照已归档；
9. 许可证、数据来源和第三方通知已审核；
10. 文档示例在安装后的 wheel 上执行通过。

## 版本管理

语义版本规则：

- patch：修复不改变公开接口和数学语义；
- minor：增加向后兼容算法、问题、算子或功能；
- major：公开 API、结果格式或算法语义发生不兼容变化。

每次发布保存源码归档、wheel SHA-256、验证 JSON、依赖锁定、硬件环境和已知限制。
可复现实验还要保存每个阶段的源码哈希，不能只记录版本号。
