# Security policy

Security fixes are supported for the latest published release. Dependency and
driver vulnerabilities should first be checked against the corresponding
upstream project because accelerator environments combine several independently
versioned components.

Use the repository's private vulnerability-reporting feature for reports that
contain exploit details, credentials, private datasets, or host information. If
private reporting is unavailable, open a minimal public issue that requests a
private contact channel and omit sensitive details.

Include the affected version, operating system, Python and PyTorch versions,
accelerator backend version, device type, reproduction steps, and expected
impact. Do not include passwords, tokens, SSH addresses, or proprietary data.
